# Accessibility Statement

## Our Commitment

Cupid Player aims to provide a music player that is enjoyable, intuitive, and accessible to as many people as possible.

Accessibility is an ongoing part of the development process. We recognize that people interact with software in different ways and that an interface that works well for one person may create barriers for another.

Although Cupid Player is currently in beta, we aim to identify and address accessibility barriers as the application evolves.

## Current Status

Cupid Player is under active development. Its accessibility features and overall conformance with accessibility standards have not yet been fully evaluated.

We therefore cannot currently guarantee full compliance with WCAG, EN 301 549, or any other accessibility standard.

Feedback from users is welcome and will help us identify areas that need improvement.

## Accessibility Goals

We aim to improve accessibility across the application, with particular attention to the following areas:

- **Keyboard navigation:** Where practical, essential controls should be accessible and usable without a mouse.
- **Visible focus:** Keyboard users should be able to identify which control is currently focused.
- **Color and contrast:** Text, icons, and interactive elements should remain distinguishable against their backgrounds.
- **Readable interface:** Text should be legible, with clear labels and a consistent visual hierarchy.
- **Screen readers:** Controls and important interface elements should expose meaningful names and roles to assistive technologies where supported.
- **Interaction feedback:** Actions, errors, and relevant state changes should be communicated clearly.
- **Motion and animation:** We aim to avoid unnecessary motion and consider users who prefer reduced animation.
- **Consistent controls:** Similar actions should behave consistently throughout the application.

These are development goals, not a claim that every item is already fully implemented.

## Reporting Accessibility Issues

If you encounter an accessibility barrier while using Cupid Player, we encourage you to report it.

You can open an issue through the repository's GitHub Issues page:

https://github.com/swogvex/cupid-player/issues

When reporting an issue, please include, where possible:

1. A brief description of the accessibility barrier.
2. The steps required to reproduce it.
3. The affected application version and operating system.
4. The input method or assistive technology involved, if relevant.
5. The expected behavior and what happened instead.
6. Any practical suggestions that might improve the experience.

Please avoid sharing personal, medical, or other sensitive information in public reports.

If you believe an accessibility issue also creates a security vulnerability, please follow the private reporting process described in `SECURITY.md` instead.

## Development and Improvements

Accessibility feedback will be considered alongside usability, reliability, and other development priorities.

We aim to address reported barriers where reasonably possible and to incorporate accessibility considerations into future interface changes.

As the project matures, we may introduce more systematic accessibility testing and document improvements in subsequent releases.

## Scope

This statement applies to the Cupid Player application and its interface maintained within this repository.

Third-party software, operating-system features, and external services may have their own accessibility limitations that are outside the project's direct control.

## Contact and Feedback

The preferred way to report accessibility issues is through the repository's GitHub Issues page.

Constructive feedback is welcome. Helping identify barriers is an important contribution to making Cupid Player more usable for everyone.
